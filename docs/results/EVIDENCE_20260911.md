## 曲线与 K=4 机制实验

已有训练图直接复制，未重新绘制：[预训练](../assets/pretrain_20260909.png)、[SFT](../assets/full_sft_20260909.png)、[DPO](../assets/dpo_20260909.png)、[CISPO](../assets/cispo_20260911.png)、[GRPO](../assets/grpo_20260911.png)。它们展示训练观测，不是 validation loss。DPO/RL 原图横轴为日志观测序号；恢复训练的历史重复尾段不能算成额外模型进度。

![K=4 机制实验](../assets/ratio_reuse_k4_20260911.png)

K=4 是独立的 120-update 探针：每个分支 30 个 prompt batch，每题 G=6，冻结 rollout 重用四次，LR=1e-6，batch=1、累积=1，seed=42。它不同于正式 RL 的 K=1、LR=3e-7、累积=2。两条探针回执均为 `probe_complete`，不是又一轮全量训练或最终质量基准。

GRPO 原生 clip 干预率在本次 120 条观测上平均为 0.0055069273（约 0.5507%）；CISPO 的宽上限干预率平均为 0。CISPO 轨迹上的 GRPO 干预率是反事实诊断，不能当作实际优化所用的 CISPO 干预率。每个总体平均值均从保留的逐步数据重新核对。不能据此推断 CISPO 提高了最终质量。

[机制摘要](ratio_reuse_k4_20260911.json) 中的 `ratio_p95` 是逐步 p95 的平均，`ratio_max` 是逐步最大值的平均，并非全部 token 混合后的分位数或全局最大值。曲线没有平滑。公开 [JSONL](ratio_reuse_k4_20260911.jsonl) 包含两算法共 240 行所需数值字段；完整原始 metrics、console 和权重仍保留在实验产物目录，未修改。

从项目根目录复画该机制图，无需模型或 GPU：

```python
import json
from pathlib import Path

rows = [json.loads(line) for line in Path(
    "docs/results/ratio_reuse_k4_20260911.jsonl"
).read_text(encoding="utf-8").splitlines()]
out = Path("artifacts/release_replot")
out.mkdir(parents=True, exist_ok=True)
for name in ("cispo", "grpo"):
    selected = [row for row in rows if row["loss_type"] == name]
    (out / f"{name}.jsonl").write_text(
        "\n".join(json.dumps(row) for row in selected) + "\n",
        encoding="utf-8",
    )
```
